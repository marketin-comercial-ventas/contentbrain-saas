- **Estado:** IN_PROGRESS

- **Requisitos:** REQ-F01-01..08, REQ-G-04/05/08 (`docs/REQUIREMENTS.md`)

- **Dependencias:** F00 aprobado (`docs/qa/f00/5c5e6f4-dirty/report.json`)

## Alcance

Resultado: cuentas de usuario, login, sesiones revocables, recuperación de
contraseña y autorización base en servidor, sin exponer negocio multiempresa.

Entregables:

1. Tablas `users`, `sessions`, `password_reset_tokens`, `audit_events`
   (globales, sin `tenant_id`; enumeradas en `docs/DATA_MODEL.md`) +
   migración `drizzle-kit generate`.
2. Hash de contraseñas con `scrypt` (node:crypto, sin dependencias nuevas);
   nunca se almacena ni expone la contraseña en claro.
3. Sesión en cookie `session` (httpOnly, SameSite=Lax, Secure en
   producción); el token de 32 bytes solo se guarda hasheado (SHA-256) en BD.
4. API REST en `src/app/api/auth/*` con validación Zod compartida
   (`src/shared/contracts/auth.ts`): `register`, `login`, `logout`, `me`,
   `forgot`, `reset`.
5. Recuperación: token temporal de un solo uso (30 min); `reset` cambia la
   contraseña y **revoca todas las sesiones**. Sin proveedor de correo en el
   repo: la respuesta incluye `devToken` **solo fuera de producción**
   (producción no lo emite); entrega por correo = integración futura
   declarada.
6. Autorización base: helpers `getCurrentUser`/`requireUser` en servidor;
   `GET /api/auth/me` devuelve 401 sin sesión.
7. Rate limiting en memoria sobre `login` y `forgot` (429 al exceder) y
   rechazo de Origin distinto en POST de autenticación (403).
8. `audit_events` con registro de `user.registered`, `auth.login_ok`,
   `auth.login_failed`, `auth.reset_requested`, `auth.password_reset`.
9. Pantallas mínimas en español: `/login`, `/registro`, `/recuperar`,
   `/restablecer` (formularios reales contra la API).
10. Evidencia en `docs/qa/f01/<commit>/`.

## Exclusiones (no forman parte de F01)

- Tenants, membresías, invitaciones, RBAC y RLS (F02) — N/A justificado en
  `docs/modules/f01.applicability.json`, acordado antes de ejecutar.
- Proveedor de correo real para recuperación → **BLOCKED** declarado
  (sin credenciales; flujo completo verificable con `devToken`).
- MFA, SSO/OAuth, sesiones multi-dispositivo con gestión UI, bloqueo de
  cuenta por fuerza bruta más allá del rate limit.
- Vercel/GitHub: bloqueo heredado de F00.

## Contratos

- `POST /api/auth/register` → 201 `{ user }` | 400 validación | 409 email.
- `POST /api/auth/login` → 200 `{ user }` + cookie | 401 | 429 | 403 Origin.
- `POST /api/auth/logout` → 200 `{ ok }` y revoca la sesión.
- `GET /api/auth/me` → 200 `{ user }` | 401.
- `POST /api/auth/forgot` → 200 `{ ok, devToken? }` (devToken solo dev/test).
- `POST /api/auth/reset` → 200 `{ ok }` | 400 token inválido/expirado.
- Objeto `user` público: `{ id, email, name, status }` — nunca
  `password_hash` ni tokens.
- Todos los POST de auth rechazan `Origin` distinto del host (403).

3. QA independiente ausente → gate BLOCKED; no se simula revisor.
4. Vercel/GitHub sin credenciales → heredado de F00.
